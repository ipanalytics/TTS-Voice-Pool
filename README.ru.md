# TTS Voice Pool

_English version: [README.md](README.md)_

**Один вызов — несколько поставщиков речи.** Ключи ротируются, когда у одного кончилась квота;
дизайнерский голос откатывается на предустановленный, когда истекает; темп держится в пределах,
которые человек способен слушать; и каждая озвучка попадает в журнал расхода, чтобы бесплатный
тариф, начавший вдруг списывать деньги, не остался незамеченным.

## Зачем это

Это голосовой слой ассистента, который говорит по расписанию: утренний выпуск, алерт, напоминание.
У задачи по расписанию никого нельзя спросить, когда голос отвалился, поэтому каждая ошибка,
которая раньше требовала решения человека, стала решением, которое код принимает сам:

* ключ упирается в квоту в 03:10, и будить никого нельзя;
* дизайнерский голос тихо истёк — выпуск либо остаётся без озвучки, либо говорит другим голосом,
  и второе слушатель замечает сильнее, чем код;
* дубль технически нормальный, но неприятный: 12 знаков в секунду «в среднем по тексту» могут
  означать 17 знаков в секунду внутри фраз;
* бесплатный тариф начинает списывать деньги, и выглядит это ровно как бесплатный тариф.

У каждой из этих ситуаций теперь есть решение, тест и абзац здесь с объяснением, что именно
замерялось. Цифры в этом README — из этой самой эксплуатации, а не из синтетического стенда.

## Что вы получаете

* **CLI `tts-voice-pool`** — `--check`, `--say`, `--say-file`, `--usage` и коды возврата, по
  которым крон может ветвиться.
* **Библиотеку** — `from tts_voice_pool import say`; падение поставщика возвращается кодом, а не
  исключением, потому что вызывающий — обычно задача, которой проще отправить текст, чем упасть.
* **Пул ключей с памятью** — состояние по каждому ключу в одном JSON: кто сработал последним, кто
  отдыхает после 429, кто выключен до замены человеком.
* **Цепочку моделей** — в файле на одну строку, поэтому откат на прежнюю модель — это правка
  текста, а не выкладка.
* **Модель темпа** — артикуляция замеряется через `ffmpeg silencedetect`, ограничивается `atempo`
  и никогда не растягивается ниже слышимого предела.
* **Журнал расхода и жёсткий месячный потолок** — после потолка следующий вызов уходит на
  бесплатный движок, а не в платный API.
* **Бесплатный откат** — `edge-tts` отдельным процессом: сломанный ключ стоит другого голоса,
  но никогда — молчания.

## Установка

```sh
git clone https://github.com/ipanalytics/TTS-Voice-Pool
cd TTS-Voice-Pool
python -m pip install -e ".[edge]"     # edge-tts — необязательный бесплатный откат
```

`ffmpeg` и `ffprobe` должны быть в `PATH`: они замеряют темп и собирают контейнер. Других
зависимостей нет — HTTP-вызовы идут через стандартную библиотеку.

## Файл с ключами

По строке на ключ: метка, `=`, ключ. Строка без `=` считается и меткой, и ключом; `#` — комментарий.

```text
main=AIza...
backup=AIza...
# laptop=AIza...
```

Источники по порядку: `GEMINI_API_KEYS` (`main=...,backup=...`), затем `TTS_POOL_KEYS_FILE`, затем
`$TTS_POOL_HOME/.gemini_tts_keys` (с откатом на `$HERMES_HOME`). Ключи читаются на каждом вызове и
никогда не попадают в файл состояния — поэтому у двух файлов могут быть разные права.

## Как проходит вызов

1. **Сначала бюджет.** Если месячный потолок уже исчерпан, вызов идёт сразу на бесплатный движок:
   платный поставщик не вызывается, чтобы узнать, что ему нельзя.
2. **Ключи в порядке последнего успеха.** Ключ, который ответил последним, пробуется первым, —
   здоровый пул сходится на одном рабочем ключе вместо перебора.
3. **Отдыхающие ключи не забываются, а сдвигаются в конец.** Если отдыхают все, попытка всё равно
   делается: пауза — это подсказка, а не приговор.
4. **Модели в настроенной цепочке.** Сбой модели переводит на следующую; ответ `quota`/`dead`
   останавливает перебор для этого ключа сразу.
5. **Откат голоса — только там, где он уместен.** Дизайнерский голос, упавший по любой причине,
   кроме квоты и смерти ключа, пробуется ещё раз предустановленным голосом. Ошибку квоты второй
   попыткой не маскируем: виноват ключ.
6. **Темп, затем кодирование.** Пришедшие байты распознаются (сырой PCM или готовый WAV),
   измеряются, при необходимости растягиваются и кодируются в тот контейнер, который просил
   вызывающий.
7. **Журнал.** Одна строка JSON на успех: ключ, голос, модель, знаки, секунды, токены и сколько это
   стоило бы в платном тарифе.

## Модель темпа

Усреднение знаков по всему файлу скрывает проблему. Замер на этом проекте: длинный выпуск, который
по всему тексту выглядел спокойным (12.3 знака/с), внутри фраз читался на 16–17 знаков в секунду — и
именно это слушатель называет «тараторит».

Поэтому замеряется только речь:

```text
артикуляция = знаки / (общие секунды - найденные паузы)     # -35 dB, 0.35 с
```

Если артикуляция выше потолка, дубль растягивается через `atempo` на `потолок / артикуляция`, но не
ниже 0.72 (дальше растяжение становится слышимым). В журнал пишется длительность **отданного**
файла, замеренная после растяжения: отчёт по числу до растяжения со временем разъезжается.

## Настройки

| Что | Переменная | Файл (в `$TTS_POOL_HOME/data`) | По умолчанию |
| --- | --- | --- | --- |
| Базовый каталог | `TTS_POOL_HOME`, затем `HERMES_HOME` | — | `~/.hermes` |
| Пул ключей | `GEMINI_API_KEYS`, `TTS_POOL_KEYS_FILE` | `.gemini_tts_keys` | пусто |
| Голос по умолчанию | `TTS_POOL_VOICE` | `tts_pool_voice.txt` | `Kore` |
| Заметки подачи | — | `tts_pool_style.txt` | пусто |
| Множитель темпа | — | `tts_pool_tempo.txt` | `1.0` (в границах 0.5–2.0) |
| Потолок темпа, знаков/с | — | `tts_pool_max_rate.txt` | `12.3` (0 — выключить) |
| Цепочка моделей | — | `tts_pool_model.txt` | `gemini-2.5-flash-preview-tts` |
| Месячный потолок, $ | — | `tts_pool_budget.json` (`{"cap_usd": 5}`) | `0` — без потолка |
| Голос бесплатного отката | `TTS_POOL_EDGE_VOICE` | — | `ru-RU-SvetlanaNeural` |
| Таймаут запроса, с | `TTS_POOL_TIMEOUT` | — | `90` |

Заметки подачи по умолчанию **не** вклеиваются в текст. Замер из этого проекта: 74 знака расшифровки
плюс заметки вернулись как ~200 знаков речи — модель прочитала заметки вслух. Поэтому заметки уходят
отдельным полем, а `TTS_POOL_PREPEND_STYLE=1` возвращает прежнее поведение тем, кому оно нужно.

## Если что-то не так

| Симптом | Обычная причина | Что делает пул |
| --- | --- | --- |
| `voice pool is empty` и код 2 | Нет файла с ключами и нет `GEMINI_API_KEYS` | Пробовать нечего; вызывающий должен отправить текстом |
| Тишина каждую ночь в один и тот же час | Квота восстанавливается во время работы задачи | Ключ отдыхает, говорит следующий |
| Голос изменился и вернулся | Один ключ в лимите, другой нет | Это норма: `--usage` показывает, какой ключ и какая модель ответили |
| Речь звучит торопливо | Модель отдала быстрый дубль | Растяжение до потолка, минимум 0.72 |
| Расхода нет вообще | Отвечал бесплатный движок | `--usage` показывает строки `edge` явно |
| `ffmpeg failed` | Нет `ffmpeg`/`ffprobe` | Вызов падает громко, а не отдаёт битый файл |

## Тесты

```sh
python -m pytest -q      # 43 passed
python -m ruff check .   # чисто
```

В тестах нет ни сети, ни звукового железа: HTTP подменён, математика темпа сверяется с известными
числами, и каждый тест получает свой `$TTS_POOL_HOME` — прогон не может тронуть настоящий журнал или
файл с ключами. Чего тесты **не** доказывают: что конкретный ключ ещё работает — ровно для этого есть
`--check`.

## Чем это не является

Это не потоковый синтез, не запуск локальных моделей и не клонирование голоса. Это небольшой слой
между «у меня несколько ключей и текст» и «на выходе играемый файл», с прописанными путями отказов —
и с бесплатным откатом, который не даёт задаче по расписанию замолчать.
