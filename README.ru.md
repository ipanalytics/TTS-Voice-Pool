# TTS Voice Pool

Один вызов — несколько поставщиков речи. Ключи ротируются, голоса откатываются на резервные,
темп остаётся человеческим, а расход видно.

Это голосовой слой ассистента, который говорит по расписанию. У задачи по расписанию никого
нельзя спросить, когда голос отвалился, поэтому каждая ошибка должна превращаться в решение,
которое код принимает сам. Именно эти решения здесь и лежат.

```sh
tts-voice-pool --say "Доброе утро. В сегодняшнем списке три пункта." briefing.ogg
# voiced by gemini-2.5-flash-preview-tts with key main -> briefing.ogg (6.4s)
```

## Какие четыре проблемы решает

**1. Один ключ — единая точка отказа.** Ошибка квоты (429) и отозванный ключ (401/403) требуют
разных действий: первый должен отдохнуть и уступить другому, второй выключен до замены человеком.
Пул держит состояние по каждому ключу (`last_ok`, `cooldown_until`, `dead_reason`) в одном JSON,
первым пробует тот, что сработал последним, а ключ с исчерпанной квотой отправляет на паузу на
несколько минут — без долбёжки и без получасовых похорон.

**2. Дизайнерский голос может истечь.** Выпуск всё равно должен быть озвучен, поэтому есть откат на
предустановленный голос — но только если виноват именно голос. Ошибка квоты — вина ключа, и второй
попыткой она не маскируется.

**3. «Знаков в секунду» по всему файлу врут.** Длинный выпуск может в среднем идти 12.3 знака/с, а
внутри фраз читаться на 16–17 — и именно это слушатель называет «тараторит». Пул замеряет скорость
*речи* (через `ffmpeg silencedetect`) и, если артикуляция выше потолка, растягивает дубль через
`atempo` — но не ниже 0.72, дальше уже слышно артефакт. В журнал идёт длительность **отданного**
файла, а не той версии, что была до растяжения.

**4. Бесплатная квота, которая тихо стала платной, выглядит ровно как квота, которая не стала.**
Каждая удачная озвучка пишет строку (секунды, токены, сколько это стоило бы в платном тире),
`--usage` превращает строки в минуты и доллары, а жёсткий месячный потолок уводит следующий вызов
на бесплатный движок вместо платного.

## Установка

```sh
git clone https://github.com/ipanalytics/TTS-Voice-Pool
cd TTS-Voice-Pool
python -m pip install -e ".[edge]"     # edge-tts — необязательный бесплатный откат
```

`ffmpeg` и `ffprobe` должны быть в `PATH`: они замеряют темп и собирают контейнер.

Ключи — по строке на ключ: метка, `=`, ключ. Строка без `=` считается и меткой, и ключом, `#` —
комментарий:

```text
main=AIza...
backup=AIza...
```

По умолчанию файл лежит в `$TTS_POOL_HOME/.gemini_tts_keys` (или `$HERMES_HOME/...`), можно указать
`TTS_POOL_KEYS_FILE`, либо передать ключи в `GEMINI_API_KEYS="main=...,backup=..."` — так пакет
работает в CI без монтирования секрета. Ключи читаются на каждом вызове и в файл состояния не
пишутся.

## Командная строка

```sh
tts-voice-pool --check                       # проверить все ключи таблицей
tts-voice-pool --say "текст" out.ogg         # озвучить, напечатать сработавший ключ
tts-voice-pool --say-file text.txt out.mp3   # взять текст из файла
tts-voice-pool --usage                       # за месяц: озвучки, минуты, условная стоимость
tts-voice-pool --voice voice_abc --style "читать спокойно" --say "текст" out.ogg
```

Коды возврата — часть интерфейса, потому что задача по расписанию больше ничего не читает:
`0` озвучено, `2` озвучить не смог никто (нет ключа и бесплатный откат тоже упал), `1` ошибка вызова.

## Как библиотека

```python
from tts_voice_pool import say

code = say("Доброе утро.", "briefing.ogg")            # 0 — озвучено, 2 — тишина
code = say("Текст", "out.mp3", voice="voice_abc", style="тепло, не спеша")
```

Падение поставщика возвращается кодом, а не исключением: вызывающий — обычно крон, которому проще
отправить текст, чем упасть.

## Настройки

| Что | Переменная | Файл (в `$TTS_POOL_HOME/data`) | По умолчанию |
| --- | --- | --- | --- |
| Базовый каталог | `TTS_POOL_HOME`, затем `HERMES_HOME` | — | `~/.hermes` |
| Пул ключей | `GEMINI_API_KEYS`, `TTS_POOL_KEYS_FILE` | `.gemini_tts_keys` | пусто |
| Голос по умолчанию | `TTS_POOL_VOICE` | `tts_pool_voice.txt` | `Kore` |
| Заметки подачи | — | `tts_pool_style.txt` | пусто |
| Множитель темпа | — | `tts_pool_tempo.txt` | `1.0` (в границах 0.5–2.0) |
| Потолок темпа, знаков/с | — | `tts_pool_max_rate.txt` | `12.3` (0 — выключить) |
| Цепочка моделей | — | `tts_pool_model.txt` | `gemini-2.5-flash-preview-tts` |
| Месячный потолок, $ | — | `tts_pool_budget.json` (`{"cap_usd": 5}`) | `0` — без потолка |
| Голос бесплатного отката | `TTS_POOL_EDGE_VOICE` | — | `ru-RU-SvetlanaNeural` |

Заметки подачи по умолчанию **не** вклеиваются в текст. Замер из этого проекта: 74 знака расшифровки
плюс заметки вернулись как ~200 знаков речи — модель прочитала заметки вслух. Поэтому они уходят
отдельным полем, а `TTS_POOL_PREPEND_STYLE=1` возвращает прежнее поведение тем, кому оно нужно.

## Тесты

```sh
python -m pytest -q      # 43 passed
python -m ruff check .   # чисто
```

В тестах нет ни сети, ни звукового железа: HTTP подменён, математика темпа сверяется с известными
числами, и каждый тест получает свой `$TTS_POOL_HOME` — прогон не может тронуть настоящий журнал или
файл с ключами. То, что требует живого API (работает ли ключ, отвечает ли модель), — как раз то, для
чего есть `--check`.

## Чем это не является

Это не потоковый синтез, не запуск локальных моделей и не клонирование голоса. Это небольшой слой
между «у меня несколько ключей и текст» и «на выходе играемый файл» — с прописанными путями отказов.
